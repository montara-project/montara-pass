# Docs App Wiring

For collections, loader, layouts, and MDX setup in `apps/docs`. Content edits (pages, `meta.json`) are out of scope → [CONTENT.md](CONTENT.md).

## Map

| File                                   | Role                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------- |
| `source.config.ts`                     | Collection definitions (`defineDocs`, `dir: 'content/docs'`)            |
| `src/lib/source.ts`                    | `loader({ baseUrl: '/', source: docs.toFumadocsSource() })` from `collections/server` |
| `src/lib/layout.shared.tsx`            | `baseOptions()`: `nav` title, `githubUrl`; shared by docs layout and 404 |
| `src/routes/$.tsx`                     | Splat route: server fn `source.getPage(slugs)` + serialized page tree; `collections/browser` client loader renders `DocsPage` + MDX inside `DocsLayout`; `head()` sets title/description |
| `src/routes/api/search.ts`             | Orama search (`createFromSource`) as a server route                     |
| `src/routes/__root.tsx`                | HTML shell, `RootProvider` (`fumadocs-ui/provider/tanstack`), site meta, CSS link |
| `src/router.tsx`                       | `getRouter()`; default 404 (`DefaultNotFound` in `HomeLayout`)          |
| `src/components/mdx-components.tsx`    | `getMDXComponents()` (currently bare `defaultMdxComponents`)            |
| `src/styles/global.css`                | Tailwind + Fumadocs UI CSS (`neutral`, `preset`) + brand palette        |
| `vite.config.ts`                       | `fumadocsMdx()`, `@tailwindcss/vite`, `cloudflare({ viteEnvironment: { name: 'ssr' } })`, `tanstackStart()`, React |
| `cloudflare.config.ts`                 | `defineWorker` (`cf/config`): name, `entrypoint: @tanstack/react-start/server-entry`, `nodejs_compat`, domain `docs.montarapass.com` |

`source.config.ts` uses the Config API (entry files generated under `.source/`, imported as `collections/*` via tsconfig paths). Do NOT mix in the macro API (`fumadocs-mdx/macro`) or hand-edit `.source/`. `src/routeTree.gen.ts` is generated by the router plugin; never edit it. See [MDX](https://www.fumadocs.dev/docs/mdx), [TanStack Start setup](https://www.fumadocs.dev/docs/manual-installation/tanstack-start).

## Operations

**Extend frontmatter / folder fields.** Edit `source.config.ts` schema:

```ts
import { pageSchema, metaSchema } from 'fumadocs-core/source/schema'

export const docs = defineDocs({
  docs: { schema: pageSchema.extend({ index: z.boolean().default(false) }) },
  meta: { schema: metaSchema.extend({ /* extra props */ }) },
})
```

Validation runs at build time; output MUST be serializable. See [collections](https://www.fumadocs.dev/docs/mdx/collections).

**Change loader behaviour.** Edit `src/lib/source.ts` only: `baseUrl`/`url()`, custom `slugs()`, `icon()` handler (map name → JSX, e.g. via an icon library), `i18n` config. API: [loader](https://www.fumadocs.dev/docs/headless/source-api).

**Change docs chrome.** Edit `src/lib/layout.shared.tsx` (`nav`, `links`, `githubUrl`) or the `DocsLayout` props in `src/routes/$.tsx` (`tree`, `sidebar`, `tabs`). Sidebar items render from the page tree; tabs come from root folders or explicit `tabs` prop. See [docs layout](https://www.fumadocs.dev/docs/ui/layouts/docs), [overview](https://www.fumadocs.dev/docs/ui).

**Change page rendering.** Edit the client loader in `src/routes/$.tsx` (`DocsPage`/`DocsTitle`/`DocsDescription`/`DocsBody`; it runs in the browser too, so only frontmatter, `toc` and the MDX body are available there, not `source`), `src/components/mdx-components.tsx` (extend `defaultMdxComponents`), `src/routes/__root.tsx` (`RootProvider` required for search/theme). See [components](https://www.fumadocs.dev/docs/ui/components).

**Static export / i18n / search.** Follow [deploying](https://www.fumadocs.dev/docs/deploying/static), [i18n](https://www.fumadocs.dev/docs/internationalization), [search](https://www.fumadocs.dev/docs/search) against this repo's wiring; don't copy standalone-starter snippets verbatim (paths/loader here already exist).

## Guardrails

- Node.js ≥ 22. `postinstall` runs `fumadocs-mdx` (typegen); `typecheck` is `tsc --noEmit` (run `build` or `dev` once first so `src/routeTree.gen.ts` exists).
- Code reachable from the client loader or components ships to the browser; keep `source` (all MDX, search index) behind `createServerFn` or server routes.
- The Worker runs on workerd, not Node: only `nodejs_compat` APIs. Check with `pnpm --filter @montara-pass/docs run preview`, not just `dev`.
- Deploy: `pnpm deploy:docs` (`cf deploy`, which builds first; `cf deploy --dry-run` checks without uploading). CI does the same in the `release-docs` job of `.github/workflows/release.yml`. `cf` and `@cloudflare/vite-plugin` 2 are betas, pinned like `apps/web`.

## Checklist

1. Change confined to the owning file in the map above; no parallel convention introduced.
2. `pnpm --filter @montara-pass/docs typecheck` and `build` pass.
3. `pnpm --filter @montara-pass/docs dev`, open `http://localhost:3001`; layout, page, sidebar and search render. For wiring that touches the server, also `preview` the build.
