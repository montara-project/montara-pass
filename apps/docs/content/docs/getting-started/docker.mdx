There are two images. Releases publish the same images
to GitHub Container Registry; see [Releases](/docs/operations/releases).

## API and web app

One image holds both: the web app is built with Vite and copied next to the Go
binary, which serves it from `./public`. The build context is the repository
root. The image also contains the `migrate` binary.

```sh
docker build -f apps/server/Dockerfile -t montara-pass-server .
docker run --rm -p 8080:8080 --env-file apps/server/.env montara-pass-server
```

`http://localhost:8080` then serves the UI, and `http://localhost:8080/api/v1` the
API.

| Path | Answered by |
| --- | --- |
| `/api/*` | the API; an unknown path under `/api` answers a JSON `404` |
| a file that exists, such as `/assets/…` | the static bundle |
| anything else without a file extension | `index.html`, so client routes survive a reload |

Run a migration with the same image:

```sh
docker run --rm --env-file apps/server/.env \
  --entrypoint /usr/local/bin/migrate montara-pass-server up
```

<Callout title="Hosting the web app elsewhere" type="info">
  Pass `--build-arg VITE_API_URL=https://api.example.com` to point the bundle
  at another origin, and list the app's origin in `CORS_ALLOWED_ORIGINS`.
</Callout>

## Docs

```sh
docker build -f apps/docs/Dockerfile -t montara-pass-docs .
docker run --rm -p 3000:3000 montara-pass-docs
```
