---
title: Sessions
description: The devices signed in to the account, and signing them out.
---

The routes are protected. A session is one sign-in: a browser, the
extension or the app on a device. Signing one out deletes it, with its
refresh tokens; its access tokens stop working on the next request, since
every request looks its session up.

```json
{
  "id": "…",
  "created_at": "…",
  "updated_at": "…",
  "expires_at": "…",
  "ip": "203.0.113.7",
  "user_agent": "Mozilla/5.0 …",
  "current": true
}
```

`updated_at` is when the session was last renewed: roughly, when the device
was last active. `current` marks the session the request was made with.

## List

```http
GET /api/v1/sessions
```

The live sessions, the most recently active first.

## Sign out a device

```http
DELETE /api/v1/sessions/:id
```

Answers `404` for a session that is not the user's, and `400` for the
current one: sign that out with
[`POST /auth/sign-out`](/api-reference/authentication#sign-out), which also clears
the session cookie.

## Sign out every other device

```http
DELETE /api/v1/sessions
```

Deletes every session but the current one. `data.revoked` says how many.
