title: Authentication

Sign-in is handled by [Authula](https://github.com/Authula/authula), mounted
at `/v1/auth`. It offers email and password, magic links and Google. This page
covers the routes the clients use; the rest follow Authula's own documentation.

These routes are **not** wrapped in the response envelope.

## Sign up

```http
POST /v1/auth/email-password/sign-up
Content-Type: application/json

{ "name": "Ada", "email": "ada@example.com", "password": "at-least-8-characters" }
```

The password must be 8 to 128 characters. The address has to be confirmed by
the emailed link before the account can sign in.

## Sign in

```http
POST /v1/auth/email-password/sign-in
Content-Type: application/json

{ "email": "ada@example.com", "password": "…" }
```

```json
{
  "user": { "id": "…", "name": "Ada", "email": "ada@example.com" },
  "session": {},
  "access_token": "…",
  "refresh_token": "…",
  "expires_at": "…",
  "expires_in": 900
}
```

| Credential | Lifetime |
| --- | --- |
| Access token | 15 minutes |
| Refresh token | 24 hours |
| Session cookie | 7 days |

## Refresh the access token

```http
POST /v1/auth/token/refresh
Content-Type: application/json

{ "refresh_token": "…" }
```

It answers a new `access_token` and a new `refresh_token`. Both clients call
it once when a request answers `401`, then repeat that request.

## Current user

```http
GET /v1/auth/me
Authorization: Bearer <access_token>
```

Answers `{ "user": …, "session": … }`.

## Sign out

```http
POST /v1/auth/sign-out
Authorization: Bearer <access_token>
```

## Roles

`public.users.role` is the application role. The only one with extra rights is
`super_user`, which may write [categories](/docs/api-reference/categories).
